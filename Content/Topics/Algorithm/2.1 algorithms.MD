## 2.1 Representing Algorithms
Algorithms can be represented in several ways, including natural language,pseudocode, and flowcharts.

### pseudocode:
Informal,programming-like way of describing an algorithm without following the exact syntax of a particular programming language.

pseudocode does not have a universal syntax. Recall the sorting algorithm in 1.3, we can represent sorting numbers in a nonempty list in pseudocode:
```
Set grades to [72,85,40,29,100,91]
for i from 0 to length - 1
    for j from 0 to length - 1 - i
        if grades[j] > grades[j+1] then
            swap grades[j] with grades[j+1]
        END if
    END FOR
END FOR
print "Sorted array: " and grades
```

# 2.3 Algorithm efficiency

When discussing efficiency, the most important things to keep in mind are computational resources.

### 2.4 how do evaluate Algorithm efficiency?
* **Time complexity:** How the number of operations grows as input size increases.
* **Space complexity:** How the memory required by an algorithm griws as input size increases.

To describe these growth rates we use Big-O notation.

First, lets go back to our previous sorting algorithm example, and improve its efficiency.
```
grades = [72,85,40,29,100,91]
length = len(grades)
for i in range(length):
    swapped = False
    for j in range(0, length-1-i):
        if grades[j] > grades[j+1]:
            grades[j], grades[j+1] = grades[j+1], grades[j]
            swapped = True
    if swapped != True:
        break
print("Sorted array: \n" + str(grades))
```
This is called an **Early Exit Optimization** where by just adding a simple boolean flag ```swapped``` detects if any changes occured, if nothing has the list has been sorted, and the algorithm exits early.

# 2.5 Time Complexity
Consider the previous sorting algorithm for sorting numbers, its time complexity is O(n^2). 

The algorithm must repeatedly step through the entire array to swap adjacent elements out of order, because the algorithm requires up to **n** passes through the list, and each pass examines up to **n** elements, it performs **nxn** total comparisons.
for larger inputs, the choice of algorithm dictates performance.


its also important to note that the performance of algorithms depends heavily on the initial state of the input data. If the data is completely sorted, the algorithm needs only **one** pass, making it the best-case time complexity O(n). When stating the time complexity of an algorithm, programmers typically default to the worst case scenario.

| Complexity | Name | Intuitive meaning | Example |
| --- | --- | --- | --- |
| `O(1)` | Constant | Work does not grow with `n` | Array index lookup |
| `O(log n)` | Logarithmic | Repeatedly reduce the search space | Binary search in a **sorted** array |
| `O(n)` | Linear | Inspect up to `n` elements | Unsorted list search |
| `O(n log n)` | Linearithmic | Split/merge or otherwise process data across logarithmic levels | Merge sort |
| `O(n²)` | Quadratic | Work grows roughly with the square of `n` | Standard bubble sort |
| `O(2^n)` | Exponential | Roughly doubles for each additional item | Enumerating all subsets |

## 2.5.1 Example: Linear search - O(n)
given an array of integers: **[70,84,91,92,100]**
```
def find_grade(grades, target):
    for index, grade in enumerate(grades):
        if grade == target:
            return index
    return -1

print(find_grade([70, 84, 91, 92, 100], 92))  # 3
```
in the **worst case**, the target is the final element or absent. Then we inspect all **n** lements. our worst case time complexity is O(n). The best case is O(1) if the first element matches.

## 2.5.2 Nested Loops - O(n^2)
```
for i in range(n):
    for j in range(n):
        print(i, j)
```
For every one of **n** outter loop iterations, the inner loop runs **n** times. **n x n = n^2**

## 2.5.4  Binary Search - O(log n)
Binary search works on **sorted** data. Compare against the middle element and discard half the remaining search range.

```
Sorted list: [2, 4, 6, 8, 10, 12, 14, 16]
Target: 14

Middle = 8  → target is larger → ignore left half
Remaining: [10, 12, 14, 16]
Middle = 12 → target is larger → ignore left half
Remaining: [14, 16]
Middle = 14 → found
```

With 1,024 possible elements, halving the range ten times leaves just one element because `2^10 = 1024`

# 2.7 Introduction to Pathfinding Algorithms
Pathfinding is the problem of finding a route from a starting location to an end destination while acknowledging permitted connections, and obstacles. Think of game characters navigating maps, robots doing automated tasks or software calculating routes (Amaps, google maps,etc)

## 2.7.1 Graphing
Think of a graph, a graph consists of:

* Vertices (nodes): locations/states
* Edges: allowed connections/move between nodes
* Weights: Costs: distance, travel time, or energy required to traverse an edge.

in mathematical terms, think of this specific graph as an incidence matrix

## 2.7.3 Breadth-First Search (BFS)
BFS checks locations **one** step away, then **two** steps away, then **three**, so on.

remember queue's property of first in, first out, that ensures earlier discovered locations are processed before later ones

# 2.9 Djikstra's Algorithm
Djikstra's algorithm introduces **weights** If BFS couns steps, Djikstra's algorithm handles nonnegative edge costs, and minimizes the sum of cost along a path.

suppose a user is travelling from S to G and has these alternatives:
```
S --1-- A --8-- G      Total cost: 9
 \                  
  2-- B --2-- C --2-- G   Total cost: 6
```

Top path: fewer edges, costs more.

Djikstra prefers the bottom route, because it **weighs**, and **costs** less (6<9).
the best-known cost from the start for each vertex and uses priority queue to process low costs first.

# 2.9.9 A* Search
* combines cost already paid with estimated cost remaining:

f(n) = g(n) + h(n)

g(n) is the best known actual cost from the start to node n.

h(n) is a heuristic: an estimate of the remaining cost from n to the goal.

f(n) estimates the cost of a complete route through n.

```
If the current cell is (1, 2) and the goal is (4, 6), the Manhattan estimate is |1−4| + |2−6| = 3 + 4 = 7 steps. Walls might force a longer route, so 7 is a lower bound when movement is limited to four directions.
```
# Best Pathfinding Algorithm?
| Problem | Good starting choice | Reason |
| --- | --- | --- |
| Any route through a maze | DFS or BFS | Easy to implement |
| Fewest steps in a maze | BFS | Equal-cost moves; shortest path |
| Cheapest route, different road costs | Dijkstra | Handles nonnegative weights |
| Cheapest route toward one goal, with a useful heuristic | A* | Combines traveled cost and estimated remaining cost |
