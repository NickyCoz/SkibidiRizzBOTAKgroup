## 2.1 Representing Algorithms
Algorithms can be represented in several ways, including natural language,pseudocode, and flowcharts.

### 2.1.1 pseudocode:
Informal,programming-like way of describing an algorithm without following the exact syntax of a particular programming language.

pseudocode does not have a universal syntax. Recall the sorting algorithm in 1.3, we can represent sorting numbers in a nonempty list in pseudocode:
```
Set grades to [72,85,40,29,100,91]
for i from 0 to length - 1
    for j from 0 to length - 1 - i
        if grades[j] > grades[j+1] then
            swap grades[j] with grades[j+1]
        END if
    END FOR
END FOR
print "Sorted array: " and grades
```

## 2.2 Improving our sorting algorithm / introduction to new sorting algorithms
Suppose our grades were already sorted
```
[29, 40, 72, 85, 91, 100]
```
our original approach **still** performs its comparisons/checks completely. So how do we go about improving it?

the solution is actually straightforward; we can simply record whether any swaps happens during a pass. if a complete pass makes no swap then we automatically know that every number is sorted.
```
grades = [72, 85, 40, 29, 100, 91]
length = len(grades)

for i in range(length - 1):
    swapped = False

    for j in range(length - 1 - i):
        if grades[j] > grades[j + 1]:
            grades[j], grades[j + 1] = grades[j + 1], grades[j]
            swapped = True

    if not swapped:
        break

print(grades)
```
we significantlly improved the efficiency of our algorithm, so what can we take away from this?

### 2.2.1 Efficiency
when comparing efficiency, ask yourself:

* how many items are checked?
* How many comparisons/movements are made?
* How much information must be stored while its working?

Sorting our list of grades in ascending order with bubble sort gives different amounts of work for how "out of order" the initial list is. 

|| Initial Data Condition | Comparisons Made | Swaps Made |
:--- | :--- | :--- | :--- |
|  | `[55, 65, 75, 85, 95]` Already sorted | 4 | 0 |
|  | `[75, 55, 95, 65, 85]` Random order | 10 | 5 |
|  | `[95, 85, 75, 65, 55]` Reverse sorted | 10 | 10 |

The easiest situation is our **best case.**

The hardest situation requiring the most work is our **worst case**

Our **average case** depends on assumptions about which inputs are likely.

### 2.2.2 Same problem, different algorithms
recall the same problem, we have a list of grades, and want to sort it in ascending order:
```
[72,85,91,68] 
```
in module 1.1 we primarily used Bubble sorting which compares adjacent numbers, and swaps them if they are in the wrong order, now we can introduce another sorting algorithm.
### 2.2.3 selection sort:
1. Look at the very first index, store whatever value is inside as the minimum
2. Use the stored minimum value and go through the array, comparing the values
3. Each time a smaller number than the minimum appears, update it to be the new minimum and keep going through the array until there are no numbers smaller than the minimum.
4. Swap the positions
5. Go to the next index, assign it as the new minimum

6. Repeat

```
[72] [85] [91] [68]
^    ^
Minimum: 72. Compare with 85: 85 < 72 == False. Min remains 72.

[72] [85] [91] [68]
^        ^
Min is 72. Compare with 91: 91 < 72 == False. Min remains 72.

[72] [85] [91] [68]
^            ^
Min is 72. Compare with 68: 68 < 72 == True. New minimum found: 68!

Swap the minimum (68) with the first element (72).
Result of Pass 1: [68] [85] [91] [72]

Pass 2: (Scan remaining unsorted part: [85] [91] [72])
[68] [85] [91] [72]
^    ^
Min is 85. Compare with 91: 91 < 85 == False. Min remains 85.

[68] [85] [91] [72]
^        ^
Min is 85. Compare with 72: 72 < 85 == True. New minimum found: 72!

Swap the minimum (72) with the first element of the unsorted section (85).
Result of Pass 2: [68] [72] [91] [85]

Pass 3: (Scan remaining unsorted part: [91] [85])
[68] [72] [91] [85]
^    ^
Min is 91. Compare with 85: 85 < 91 == True. New minimum found: 85!

Swap the minimum (85) with the first element of the unsorted section (91).
Result of Pass 3: [68] [72] [85] [91]

Final output:
[68] [72] [85] [91]
```

### 2.2.4 Insertion sort
remember our array [72,85,91,68]

1. Skip the first index [0], a single  element is always sorted.
2. Examine the next element, store it at the current index as our current value. we call this value the **key**.
3. Compare the key with the element to its left, if its smaller then shift that element to the right.
4. Keep comparing the key to its left until the key is greater than the element or you reach the start of the array
5. **Insert** the key into the empty position.
6. move to the next index, repeat the process until the elements have been inserted into its correct position.
```
[7 | 4, 9, 2, 5]

[4, 7 | 9, 2, 5]

[4, 7, 9 | 2, 5]

[2, 4, 7, 9 | 5]

Final output: [2, 4, 5, 7, 9]
```
in a sense were creating a partition to divide the left side into the sorted portion, and the right side into the unsorted portion.

## 2.3 Searching
### 2.3.1 Linear search
if sorting arranges items, searching finds a particular item.

Linear search, at its core is essentially a way to find a target by examining elements one by one.

#### given an array of integers: [72,85,91,68] you're assigned to find 68.
finding 68 itself requires **4** checks, finding 91 requires **3**, finding 85 requires **2** , finding 72 requires **1**.



**Linear search**:
1. start at first index (0)
2. Compare the current element with the target.
3. If the value matches, stop searching.
4. If values doesnt match, move to the index, compare next element with target.
5. Repeat until target found

#### Implementation (python):
```
array_one = [72,85,91,68]
length_arr = len(array_one)
for i in range(length_arr):
    if array_one [i] == 68:
        print("found 68 at index" + str(i))
```
#### output: found 68 at index 3
**Important distinction:** searching is not the same as sorting, were just trying to find where the target is located.

Something else to note is the fact that linear search works whether the array is sorted or unsorted.

### 2.3.2 Binary search
Now ask yourself:

1. what happens as the dataset grows? what if our array has a million or more elements?

2. What happens if our target is at the end of said array?

Linear search would prove to be massively inefficient at that scale.

If Linear search checks one by one, binary search repeatedly eliminates half of remaining possibilities with one requirement:
**The dataset must be sorted**
#### given an array of integers: [1,3,5,7,9, 11, 13] we want to find the target: 11

1. Find, and examine the middle of the array.
2. Compare the value of the element with our target
3. if value is bigger than target, we can eliminate the entire right half including the value.
4. if value is smaller, eliminate entire left half, including the value.
5. Repeat until target is found or there are no elements left to search.

#### To find, and examine the middle element, think of the midpoint formula:
```
Minimum + Maximum
__________________
        2
```

in our given array, the 0'th index + the 6'th index / 2 evaluates to 3, so our middle elemnt is at index 3.

so were finding the midpoint between indices, which can be represented as:

```
mid = [left+ right / 2]
```

Left = index of first 
element in search range.

Right = End of search range

Mid = Indx of middle element

### Implementation (Python)
```
def binary_search(arr, target):
    low = 0
    high = len(arr) - 1

    while low <= high:
        mid = (low + high) // 2
        if arr[mid] == target:
            return mid

        elif arr[mid] < target:
            low = mid + 1

        else:
            high = mid - 1
    return -1

numbers = [10, 23, 35, 42, 57, 68, 71, 85, 92]
target_value = 68

index = binary_search(numbers, target_value)
print(f"Target {target_value} found at index: {index}")
```
Output: Target 68 found at index: 5

## 2.4 Introduction to Time Complexity

Take a look at all of our examples so far:
* Bubble sort
* Selection sort
* Insertion sort
* Linear search
* Binary search

We've been using small examples, and datasets. now 
let **n** mean the number of items in the array. Time complexity describes how the number of operations on an algorithm grows as input size increases.

Take this example:
| Number of items | Linear search: maximum items checked | Binary search: maximum middle items checked | Bubble sort shown above: maximum neighboring comparisons |
| --- | --- | --- | --- |
| 10 | 10 | 4 | 45 |
| 100 | 100 | 7 | 4,950 |
| 1,000 | 1,000 | 10 | 499,500 |

These are the **worst** case scenarios, and they take particular actions, **not**  runtime. 

#### Remember, Time complexity is concerned  with how the amount of work grows as input gets larger.

## 2.5 Recursion and Call stack
### 2.5.1 What is recursion?
Heres the definition: "a **technique** where a function calls itself directly or indirectly to solve a smaller version of the problem.

Essentially, its when a function solves a problem by calling itself.

heres an introduction using assignments already given to us during our lecture about loops:

### Iterative implementation (C)
```
#include <stdio.h>
int main(void)
{
    int num1;
    long long sum = 1;
    if (scanf("%d", &num1) != 1)
    {
        printf("Invalid integer");
    }
    for (int i=1; i<=num1; i++)
    {
        sum = sum * i;
    }
    printf("%lld\n", sum);
}


```
### Recursive implementation (Python)

```
def factorial_recursive(n):
    if n < 0:
        return "Factorial is not defined for negative numbers."
    if n == 0 or n == 1:
        return 1
    return n * factorial_recursive(n - 1)

# Example usage:
print(factorial_recursive(5))  # Output: 120
```
both calculates factorials of any given integer, but one handles it differently. Lets take a closer look at the recursive implementation.

first, we need to know the components of recursions:
1. Base Case:  The simplest possible version of the problem that can be answered immediately. This stops the function from calling itself forever.
2. Recursive Case: The step where the function breaks the problem down into a smaller problems and calls itself to solve it, moving towards the base case.

Everytime the function calls itself it reaches towards the base case by reducing n by 1:
```
factorial_recursive(5)
│
│ 5 is not 0 or 1
│ return 5 * factorial_recursive(4)
│
└── factorial_recursive(4)
    │
    │ 4 is not 0 or 1
    │ return 4 * factorial_recursive(3)
    │
    └── factorial_recursive(3)
        │
        │ 3 is not 0 or 1
        │ return 3 * factorial_recursive(2)
        │
        └── factorial_recursive(2)
            │
            │ 2 is not 0 or 1
            │ return 2 * factorial_recursive(1)
            │
            └── factorial_recursive(1)
                │
                │ 1 == 1 → BASE CASE!
                └── return 1
```
what happens after we reach the base case?
```
factorial_recursive(1)
    │
    └── returns 1
         │
         ▼
factorial_recursive(2)
    │
    └── returns 2 * 1 = 2
         │
         ▼
factorial_recursive(3)
    │
    └── returns 3 * 2 = 6
         │
         ▼
factorial_recursive(4)
    │
    └── returns 4 * 6 = 24
         │
         ▼
factorial_recursive(5)
    │
    └── returns 5 * 24 = 120
         │
         ▼
    FINAL OUTPUT: 120
```
### 2.5.2 Call stack
Recall 2.5.1 where we introduced recursion, ask yourself again:

1. how does the program know where it left off?
2. how does the program know which function it should return to?

Call stack: a data structure that keeps track of active function calls during a program's execution. Whenever a function is called, the program adds a new entry, known as a stack frame, to the call stack.

Every time a function calls itself, the program pushes a new stack frame, onto the call stack using a Last-in, First-out (LIFO) order.

adding a function: push

removing a function: pop

since it goes in the order of last in, first out, the newest call must be evaluated and 'popped' first (LIFO).

implementation with our factorial calculator:
```
        Top
    ┌──────────────────┐
    │ factorial(1)     │ ← Base case reached
    ├──────────────────┤
    │ factorial(2)     │ ← Waiting
    ├──────────────────┤
    │ factorial(3)     │ ← Waiting
    ├──────────────────┤
    │ factorial(4)     │ ← Waiting
    ├──────────────────┤
    │ factorial(5)     │ ← Waiting
    └──────────────────┘
          bottom
```
When factorial(1) returns 1, its stack frame is removed.

Then factorial(2) can finish, followed by factorial(3), and so on.
